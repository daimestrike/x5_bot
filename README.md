# Справочный бот Аватара в Rooms (MVP v9)

Помощник Аватара при удалённой ПИ: меню, кнопки, 35 согласованных карточек по пяти разделам,
поиск по ключевым словам, маршрут помощи и журнал обращений. Без ИИ, без рассылок, без интеграций
с Inventa/GK — ровно по документу «MVP бота Rooms v9» и файлу чек-листов v9.

## Что внутри

```
app/
  engine.py          диалог: экраны S0–S8 и переходы (лист «Экраны и кнопки»)
  content.py         загрузка и проверка карточек (лист «Правила ответов»)
  search.py          поиск по подстроке: заголовок, синонимы, текст; 1–2 слова
  journal.py         журнал обращений в SQLite, без персональных данных
  metrics.py         сводка по листу «Метрики»
  sessions.py        сеансы пользователей (приветствие S0 — один раз за сеанс)
  main.py            HTTP: webhook Rooms, демо-консоль, метрики, health
  transports/rooms.py адаптер Bot API Rooms — единственное место, зависящее от мессенджера
  static/index.html  демо-консоль для приёмки (открывается на /)
content/
  cards.yaml         35 карточек — правит владелец содержания, без разработчика
  screens.yaml       тексты и подписи кнопок экранов
  help_routes.yaml   экран S6/S6a: порядок обращения и контакты (заполнить!)
  params.yaml        ссылки на инструкции, имя сети — изменяемые параметры
scripts/
  import_registry.py импорт листа «Реестр материалов» из xlsx в cards.yaml
  validate_content.py проверка содержания (длина, шаги, секреты, версия, владелец)
  export_journal.py  выгрузка журнала в CSV + сводка метрик
tests/               40 тестов: чек-лист «Приёмка MVP» и сценарии диалога 1–13
```

## Быстрый старт (локально)

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
python scripts/validate_content.py
python -m pytest -q
uvicorn app.main:app --port 8080
```

Откройте http://localhost:8080 — демо-консоль. Она ходит в тот же движок, что и Rooms,
поэтому по ней можно пройти весь лист «Приёмка MVP» до подключения мессенджера.

## Docker

```bash
cp .env.example .env   # заполнить ROOMS_* и JOURNAL_SALT
docker compose up --build -d
curl localhost:8080/health
```

Каталог `content/` монтируется в контейнер только для чтения: правка карточки = правка YAML +
`docker compose restart bot`. Пересборка образа не нужна. Журнал лежит в `./data/journal.sqlite3`.

В закрытом контуре задайте `PIP_INDEX_URL` (зеркало PyPI в Artifactory) — он передаётся
в `docker build` и в CI.

## Подключение к Rooms

Бот работает по схеме webhook: Rooms присылает событие на `POST /webhook/rooms`,
бот отвечает через Bot API Rooms (`ROOMS_API_BASE_URL` + `ROOMS_SEND_PATH`, токен `ROOMS_BOT_TOKEN`).

Публичной документации на Bot API Rooms нет, поэтому формат зафиксирован в одном файле —
[app/transports/rooms.py](app/transports/rooms.py) — и при подключении к контуру нужно сверить с документацией
команды Rooms две функции:

| Функция | Что уточнить |
|---|---|
| `parse_update(payload)` | имена полей: id пользователя и чата, текст, данные нажатой кнопки, вложения. Сейчас понимает распространённые варианты (`user_id`/`from.id`, `chat_id`/`chat.id`, `text`, `callback_data`, `callback_query`) |
| `build_payload(...)` | тело запроса на отправку: сейчас `{"chat_id", "text", "buttons": [[{"text","callback_data"}]]}` |

Если Rooms не поддерживает inline-кнопки — поставьте `ROOMS_BUTTONS_MODE=text`: кнопки печатаются
нумерованным списком, Аватар отвечает номером («2») или подписью («Меню»). Движок понимает оба
варианта всегда, независимо от режима.

Секрет webhook: `ROOMS_WEBHOOK_SECRET` — проверяется в заголовке `X-Rooms-Token` (или `Authorization: Bearer`).

Тело ответа webhook содержит сформированные сообщения (`messages`) — пригодится, если Rooms умеет
синхронный ответ на webhook, тогда исходящий вызов API можно не настраивать.

## Как работает диалог

| Экран | Когда | Кнопки |
|---|---|---|
| S0 приветствие | один раз в начале сеанса (после `SESSION_TTL_MIN` минут тишины сеанс новый) | Меню |
| S1 меню | «Меню», после ответа | 5 разделов · Поиск · Помощь человека |
| S2 раздел | выбор раздела; до 8 тем, «Ещё темы» при большем числе | темы · Назад |
| S3 карточка | заголовок, шаги, «Подробнее: источник — ссылка» | Помогло · Не помогло · Другие темы · Меню |
| S3a / S4 / S4a | оценка; причина «Не помогло» пишется в журнал | … |
| S5 / S5a / S5b | поиск: 1–2 слова, до 5 тем; нет результата — запрос в журнал как пробел базы | … |
| S6 / S6a | помощь человека по трём типам (`help_routes.yaml`) | Меню |
| S7 | фраза из 3+ слов, вложение, «спасибо», просьба сделать что-то в GK/Inventa | Меню · Поиск |
| S8 | сбой выдачи материала (любое исключение) — ссылка на инструкцию и помощь | Помощь · Меню |

Правила из MVP выполняются кодом и проверяются тестами: возврат в меню за одно нажатие с любого экрана,
до карточки — не более трёх нажатий без ввода текста, бот пишет только в ответ.

## Содержание: как править без разработчика

1. Откройте `content/cards.yaml`, найдите карточку по ID (`A-07`), измените `steps`, поднимите `version`
   и `updated`, укажите `owner`.
2. Запустите `python scripts/validate_content.py` — проверит длину заголовка (≤60), текста (≤600),
   число шагов (≤6), наличие версии/владельца/ссылки и предупредит о словах «пароль»/«код».
3. Перезапустите бота. CI делает ту же проверку на каждый коммит в `content/`.

Обновить все карточки из нового xlsx: `python scripts/import_registry.py "Чек-листы_бота_Rooms_vN.xlsx"`
(версии/владельцев после импорта проставить в YAML).

Ссылки на документы и имя корпоративной сети — в `content/params.yaml`; контакты маршрута помощи —
в `content/help_routes.yaml`. Сейчас там заглушки «укажите контакт…» — это открытый вопрос №5 из MVP.

## Журнал и метрики

Таблица `events` в SQLite: время, сеанс, хеш пользователя (SHA-256 с солью `JOURNAL_SALT`), тип события,
карточка и её версия, оценка, причина уточнения, поисковый запрос, тип помощи. Идентификаторы Rooms
и содержание ПИ не хранятся. Запись текста запросов без результата и свободных фраз можно отключить
(`LOG_FREE_TEXT=false`).

- `GET /metrics/summary?since=2026-09-01&until=2026-10-01` — сеансы, обращения, охват оценкой,
  полезность, пробелы базы (темы с «Не помогло», запросы без результата, частые фразы), запросы помощи.
- `GET /metrics/journal.csv` — выгрузка журнала.
- `python scripts/export_journal.py --since 2026-09-01` — то же из контейнера/консоли.

Если задан `METRICS_TOKEN`, эндпоинты требуют заголовок `X-Metrics-Token`. Показатели «на одну ПИ»
считаются вручную сопоставлением сеансов с ПИ по времени — как описано в MVP.

## CI (GitLab)

`.gitlab-ci.yml`: проверка содержания → lint (ruff) → тесты (junit-отчёт) → сборка и push образа
в registry проекта на default-ветке и тегах. Переменные проекта: `PIP_INDEX_URL` (зеркало PyPI),
опционально `DOCKER_IMAGE`.
