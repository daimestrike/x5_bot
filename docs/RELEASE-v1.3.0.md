# Релиз v1.3.0 — заметки

Архив самодостаточный: **все зависимости вложены**. На сервере не нужны интернет, pip, venv,
Docker и внутреннее зеркало PyPI.

## Требования к серверу

- Ubuntu, **Python 3.10**, архитектура **x86_64**.
- Больше ничего. Двоичные модули (cryptography, pydantic-core, PyYAML, cffi) собраны под эту связку.

Если на сервере другой Python или ARM — пересоберите поставку на машине с интернетом:

```bash
python scripts/vendor.py --python-version 3.11 --arch aarch64
python scripts/package.py --name rooms-bot-1.3.0
```

## Установка

```bash
sudo mkdir -p /opt/rooms-bot && sudo chown "$USER" /opt/rooms-bot
tar xzf ~/rooms-bot-1.3.0.tar.gz --strip-components=1 -C /opt/rooms-bot
cd /opt/rooms-bot
./setup.sh        # создаёт .env и проверяет содержание; ничего не скачивает
./start.sh
```

Диалог — <http://127.0.0.1:8080/dev/chat>, метрики — `/metrics/dashboard`, содержание — `/content/`.

Как служба, чтобы поднималась после перезагрузки:

```bash
sudo cp deploy/rooms-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now rooms-bot
```

## Обновление

```bash
cd /opt/rooms-bot && ./update.sh ~/rooms-bot-1.3.0.tar.gz --service rooms-bot
```

Проверяет контрольную сумму, делает резервную копию, меняет код и `vendor/`, перезапускает службу.
`.env`, журнал `data/` и содержание `content/` остаются от установки. При ошибке код откатывается
из `backups/`.

## Что нового

**ИИ-ответ по базе знаний (RAG).** Вопрос, написанный фразой, больше не упирается в «понимаю только
меню»: поиск находит фрагменты в карточках и загруженных документах, модель отвечает **только по ним**
и ссылается на карточки кодами `[A-07]` — коды становятся кнопками, под ответом привычные
«Помогло / Не помогло».

- `app/llm.py` — клиент OpenAI-совместимого API на стандартной библиотеке (X5 CoPilot, vLLM, Ollama,
  LiteLLM, TGI): свой CA, системный прокси выключен, `<think>` у reasoning-моделей вырезается.
- `app/rag.py` — BM25 с русским стеммингом; эмбеддинги необязательны (RRF, кэш в отдельном SQLite).
- `app/assistant.py` — связка поиска и модели; ответ без ссылок помечается как неподтверждённый.
- Вкладка **ИИ** на `/content/`: состояние, размер индекса, проверка связи с моделью.
- `scripts/mock_llm.py` — заглушка модели: конвейер проверяется без доступа к контуру.

По умолчанию `AI_ENABLED=false` — бот работает строго по меню и поиску, как в MVP. Сбой или таймаут
модели не ломает диалог. Запрос к модели выполняется вне транзакции SQLite и в пуле потоков.

Включить: в `.env` задать `AI_ENABLED=true`, `AI_URL` (вместе с `/v1`), `AI_MODEL`, перезапустить.

**Поставка и эксплуатация.** `vendor/` с зависимостями, `update.sh` с резервной копией и откатом,
systemd-юнит в `deploy/`, раздел «Быстрые команды» в начале README, `scripts/vendor.py` для пересборки
под другую версию Python или архитектуру.

## Что в архиве

76 файлов проекта и 786 файлов зависимостей, 8.8 МБ. Не входят: секреты и `.env`, журнал `data/`,
слепки документов, очередь проверки, внутренние материалы в `.docx`.
Контрольная сумма — в `rooms-bot-1.3.0.tar.gz.sha256`.

## Что проверено

- 125 тестов и `ruff` — чисто; тесты проходят и в распакованном архиве.
- Установка из архива и обновление поверх рабочей установки: `.env`, журнал и правки содержания
  сохраняются, при неудачной проверке конфигурации код откатывается.
- Состав `vendor/`: 23 пакета, двоичные модули — Linux ELF x86_64, CPython 3.10.
- **Не проверено исполнением:** запуск на самом Ubuntu с Python 3.10 — на машине сборки нет ни Linux,
  ни Docker. Набор пакетов получен pip-ом ровно под эту платформу, но первый запуск на сервере стоит
  делать с `./start.sh --check`.
